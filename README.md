## 파이토치 도커 이미지 기반 컨테에서 파이토치 재설치 방지

#### 방법 1. UV_SYSTEM_PYTHON=1 + --no-editable 활용 (가장 추천)
도커 컨테이너 내부에서는 별도의 가상환경(.venv)을 생성하지 않고, 이미지 자체의 시스템 파이썬 환경에 패키지를 바로 동기화하는 방법입니다. 다른 시스템에서는 정상적으로 가상환경을 만들어 사용할 수 있어 호환성이 가장 좋습니다.

실행 명령어:
```bash
export UV_SYSTEM_PYTHON=1
uv sync --frozen --no-editable
```

- UV_SYSTEM_PYTHON=1: uv가 .venv를 만들지 않고 도커 이미지 내부의 글로벌 파이썬 환경을 타겟으로 삼도록 만듭니다.
- --frozen: uv.lock 파일에 명시된 버전 그대로 설치하여 의존성 충돌 및 임의 업데이트를 방지합니다.
- --no-editable: uv sync는 기본적으로 현재 프로젝트를 에디터블(Editable) 모드로 시스템에 설치하려고 시도하는데, 도커 빌드 환경에 따라 이 과정에서 에러가 날 수 있으므로 이를 방지합니다.

#### 방법 2. --system-site-packages 가상환경 활용
도커 내부에서도 반드시 프로젝트 폴더 내에 .venv 가상환경이 생성되는 구조를 유지해야 한다면, 기존 도커의 파이썬 패키지들을 상속받는 가상환경을 만들어야 합니다.

실행 명령어:
```bash
# 1. 시스템 패키지를 공유하는 가상환경 생성
uv venv --system-site-packages

# 2. 가상환경에 동기화
uv sync --frozen --no-editable
```

이렇게 하면 uv는 가상환경 내부를 먼저 검사하고, 부족한 패키지는 글로벌(도커 이미지) 환경에서 찾아서 연결하므로 PyTorch를 새로 다운로드하지 않습니다.
